# Python widget factories on the shipped TDL views (design, step 1)

Evidence: read the sources; ran two throwaway probes in /tmp/facexp (compose `Button{...}` against a Python object, build a `ComposedView`; compose `ButtonGroup`, `Chip`, `Menu`) - they confirm everything marked (verified). Marked [INFERENCE] = not run.

## 1. Mechanism
1. **One call tree per widget, values never in the text.** New `widgets/_views.py`: `Call(widget, name=None, props={}, style={}, children=[])` renders TDL such as `Button { Label: <| label |> Variant: <| variant |> Style { Width: <| width |> } }` (header `---/TDL: 0.2/Name: Factory/Tesserae: "0.6"/---`). Each prop value is an attribute of a small `_Params` object (a `Signal` for what changes at run time: label, selected, text, query; a plain value otherwise), so nothing needs TDL escaping and the snippet text is per factory, not per call: its `ViewDoc` (`parse_view(text, resolver=lib.decl)`) is cached by text. Style overrides (`width`, `height`, `corner_radius`, `border_*`, `x/y` stay on `node.set`) are call-site `Style {}`: inline wins over the shipped rules (verified: `Corner_Radius`, `Width`, `Height` held over the Button rules).
2. **Composing.** One module-level `ViewLibrary()` (shipped views only: a project's own `Button_View.tdl` must not leak into a factory widget, as fragments were internal). `rules = lib.sheets_of(lib.used(doc))[0]`; `Composer(lib.doc, params, rules=rules).compose(doc, root_id=name)`; `ViewHandle(None, comp, params, None, doc)`; `FactoryView(ComposedView)(handle, window=, theme_seed=BASELINE primary, frames=)` (verified; no Bindings, no App needed). New code: `root_id=` on `Composer.compose` (spec/compose.py:789 hard-codes `"root"`; it is the only place) and `open_factory_view()` beside `open_composed` (composed.py:1319). Ids then are `name` and `name.<part>` as today; `If` adds no level (verified `root.label`, `root.icon`); `For` rows are `item[<key>]`, a Menu row is `surface.row[i].item` (verified).
3. **`fragment()` goes.** `fragment(name, params, id)` returned a kind-tree dict to embed in other dicts. Its callers that embed (button_group, Dialog/Snackbar/Menu actions and items) become one `Call` tree: `Call("Container", style=..., children=[Call("Button", name="b0", ...)...])` - a builtin container plus view calls in one TDL text. `Widget(window, spec=...)` (a hand-built kind-tree through `View`) stays for what has no shipped view (section 3 last row) and for rail/tabs/drawer/pagination/etc., which never used a fragment.
4. **`Widget` on a call tree.** `Widget(window, call, *, tag=None, parts=None, interaction=None, ...)`. `.view` is the `FactoryView`; `.node`, `.interaction(part)`, `.on_click`, `.set_theme` (`_layers.components/typography`, `_use_scheme`: inherited from `View`), `after_theme`, `color`, `dispose` (add `view.close()`: `handle.close` disposes the composition and the effect) are unchanged. `.part(name)` = `view.node(ids[name])` where `ids` is `name.<name>` by default, overridden by a per-factory table of aliases (`"check": "icon"`, `"item2": "surface.row[2].item"`) or a callable for ids that move (StatusBar). `_spec_of`/`edit(spec)`/`content_role` go: the `edit` hacks (inserted icons, borders, padding) become call props and style.
5. **State and interaction.** A `Signal` the factory owns (`widget.selected`, `.expanded`, `.query`, `.period`, `.content`, `.day/selected/today/outside_month`) is *the same object* as the view's model param: a bare `Signal` given to a `Model: true` param is shared, so the view's own handlers write it and the factory's `Effect(paint)` code, the manual rotation and the `on_*` plumbing are deleted (`on_change`/`on_query` = an `Effect` or the view's `On_*` handler -> `Composer(actions=...)`). State layer, ripple and focus ring come from the shipped `Interaction: true` (colour = content colour, i.e. today's role per variant: verified identical for Button; verified `interaction(root)` exists). Explicit factory roles (`on_surface`) pass as the call's `Interaction: <role>` (a constant; "cannot change while open"). `on_click(fn, part, role)` stays a `Widget` method on the built node (`_listen`, `focusable`, `role`, `cursor`), so callbacks, undo and the `part=` argument do not change.
6. **Theme `components:` (M57).** `lower()` never emits `component_of`, so a composed view gets no `components:` shape (finding: this is also true of every app TDL view call today). Factories tag their root: `FactoryView._lowered` returns the root dict with `component_of` set, using the dotted form `component_key` already accepts (`"fab.small"`, `"button.filled_tonal"`, `"card.elevated"`, `"chip.filter"`, `"icon_button.outlined"`, `"toolbar.docked"`, `"dialog"`). `_VARIANT_FAMILIES`, `_EXACT_KEYS`, `_snake` and the name branch of `component_key` then die with the fragments; `test_component_key`/`test_theme_components` are rewritten on dotted keys. Alternative for the maintainer: make `lower` tag every view-call root with `snake(widget)` + its `variant` param (fixes app views too, but changes them).
7. **Costs to measure in step 2 [INFERENCE].** A `ComposedView` runs ~15 `_wire_*` passes and TEL-compiles each prop (cached per snippet); widget-heavy tests and apps get slower per widget than `View(spec)`. Perf budget is 16 ms with a thin margin: time 200 factory calls before/after.

## 2. Gaps that cut across families
- **Pixel sizes vs size tokens.** Factories take `width/height/corner_radius` in pixels; shipped views take `Size` (32/40/56/96/136) and size themselves. Map: nearest `Size` for type/gap/icon size (always `s` for buttons: label_large, 8 gap) plus call `Style` for the exact pixels. Fixed widths hide the shipped padding (24 vs 12); only an overflowing label shows it.
- **Transitions.** Button/Chip/Fab rules animate Background (150 ms), Corner_Radius and Elevation (200 ms). `fill`/`corner_radius` read right after a state or theme change are mid-animation, and `set_theme` ("at once") may animate [INFERENCE]; step 2 must test it, mitigation `motion`-reduced or `Transition {}` on the call.
- **Hover lift** (filled/tonal/elevated/Fab elevation + 1) and **press shape** (Button corner radius while pressed) are new (the shipped look, not in fragments).
- **App stylesheet.** Factory views get only shipped sheets plus the follow-the-app theme as today; `App(stylesheet=)` rules do not reach them [INFERENCE: same as fragments, whose look was baked in].
- **`Overlay` widget needs `app`.** Shipped `Snackbar` places itself with `app.window_width`; factory widgets live on bare windows with no `App`.

## 4. Behaviour changes that cannot be avoided (to list in the changelog)
`fab` theme key `fab.default` -> `fab.medium`; part-id renames above (`check`, `remove`, `indicator`, `am/pm`, `trailing{i}`, `chevron` of the split button, status text); Badge, Accordion, Card roots wrap more; Dialog height auto + scrim closes; Snackbar/Tooltip/NodeGraph/window-controls TopAppBar stay hand-built; search bar takes one trailing icon unless the shipped view grows a list; hover lift, press shape, icon-button tooltip, link underline, animated state changes; a11y roles of Period/Accordion; per-widget cost (section 1.7).
